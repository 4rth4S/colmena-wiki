Colmena sits between Claude Code and your filesystem. Every tool call — Bash, Write, WebFetch — passes through a **deterministic firewall** that evaluates rules, delegations, ELO trust scores, and mission gates. Under 100ms. No network calls. No databases. Just YAML, JSON, and Rust.

## How it works

<CardGrid stagger>
  <Card title="1. Define your roles" icon="setting">
    Write a role YAML: which tools, which scope, which trust level. Colmena ships with 15+ pre-built roles — pentester, auditor, developer, architect, and more.
  </Card>
  <Card title="2. Spawn a mission" icon="rocket">
    One command. <code>colmena mission spawn</code> reads a manifest, resolves the pattern, composes agent prompts with mission markers, and creates time-boxed delegations.
  </Card>
  <Card title="3. Agents work scoped" icon="activity">
    Every tool call hits the PreToolUse hook. The firewall checks: blocked? delegated? YAML override? ELO override? mission gate? If nothing matches, ask the human.
  </Card>
  <Card title="4. Audit closes the loop" icon="check-circle">
    Workers submit reviews. The auditor scores QPC (Quality, Precision, Comprehensiveness). Scores feed ELO. ELO shapes future trust. The cycle closes.
  </Card>
</CardGrid>

## Built for real workflows

<CardGrid stagger>
  <Card title="Pentest BBP" icon="shield">

  <Card title="Code Review" icon="code">

  </Card>

## Why YAML, not prompts

Colmena's firewall is **deterministic**. Rules are YAML, evaluated in a fixed precedence chain. Human overrides always beat ELO. Runtime delegations expire. The audit log records every decision with the matching rule ID — not an LLM's best guess. When you need to know why an agent was allowed to `rm -rf`, the answer is in `audit.log`, line 847.
